This page documents the visual language established by the client-approved HTML prototype (role-picker → Super Admin / Water Purveyor / Certifier flows). Treat it as the baseline for the real Next.js + Tailwind implementation — new screens should read as part of the same system, not a fresh design.

## Color palette

| Token | Hex | Use |
|---|---|---|
| Primary | `#2F6FED` | Primary buttons, active nav item, links, focus accents |
| Primary hover | `#2A63D4` | Primary button hover |
| Primary tint | `#EAF1FE` | Active nav background, primary badge background, icon chip background |
| Text primary | `#1D2129` | Headings, body text |
| Text secondary | `#6B7280` | Labels, meta text, muted descriptions |
| Text tertiary | `#9AA1AC` | Placeholders, disabled text, inactive tab icons |
| Border strong | `#E4E7EC` | Card borders, table header border, sidebar border |
| Border soft | `#EDEFF2` | Section dividers, input read-only background context |
| Border input | `#D9DDE3` | Input/button borders |
| Row divider | `#F1F2F4` | Table row borders |
| Page background | `#F4F5F7` | App shell background |
| Surface | `#FFFFFF` | Cards, sidebar, table, modal |
| Success | `#16A34A` text / `#DCFCE7` bg | Pass badges, positive stats |
| Danger | `#DC2626` text / `#FEE2E2` bg | Fail badges, past-due, blocked |
| Warning | `#D97706` text / `#FEF3C7` bg | Due-soon badges, mid-wizard warnings |
| Accent (secondary) | `#0D9488` text / `#CCFBF1` bg | Secondary stat-card accent (submissions, no-BIN count) |
| Purple | `#7C3AED` text / `#EDE9FE` bg | Agricultural-rate badge |

Dark colors never appear as full backgrounds in this system — every accent is a saturated text color paired with a pale tint background (badges, stat-card icon chips). Keep that pairing when adding new states rather than inventing new backgrounds.

## Typography

- Font stack: `-apple-system, BlinkMacSystemFont, 'Segoe UI', Helvetica, Arial, sans-serif` — no custom webfont.
- Body/UI text: 13–14.5px, weight 400–600.
- Section/page headings: 15.5–20px, weight 700.
- Labels above inputs: 12px, `#6B7280`.
- Badges/pills: 11px, weight 600.
- Letter-spacing `.03–.05em` + uppercase only on small eyebrow labels (section labels, menu group headers).

## Spacing & radius

- Card / table / modal radius: **10–12px**. Buttons and inputs: **8px**. Badges/pills: **6px**.
- Card padding: 16–24px. Table cell padding: `11px 16px`. Input padding: `10px 12px`.
- Card border: `1px solid #E4E7EC` (or `#EDEFF2` for a lighter nested card) plus a subtle shadow `0 1px 2px rgba(16,24,40,0.04)` — never a heavier shadow.
- Gaps between grid items / stat cards: 14–16px.

## Layout shell

- **Certifier (mobile-first):** phone width uses a bottom tab bar (Dashboard / Profile); desktop width (≥780px) switches to the same 216px left sidebar used by WP/Admin. Content max-width `480px` centered on desktop for forms, full-width for tables.
- **WP / Super-Admin (desktop-oriented):** fixed 216px left sidebar (white, `1px solid #E4E7EC` right border), icon + label nav items, active item gets `#EAF1FE` background + `#2F6FED` text/icon. Top header bar (white, bottom border) shows the current WP/company name and a "Switch role" or contextual action on the right.
- **Impersonation banner:** full-width `#FEF3C7` bar above the shell, `#92400E` text, with an underlined "Exit impersonation" link — always visible while impersonating, never folded into a menu.

## Components

**Stat card** — white card, radius 12px, a 3px colored top accent bar (`#2F6FED` primary metrics, `#0D9488` secondary/computed metrics, `#DC2626` for danger metrics like past-due count), a 32–38px icon chip in the matching tint color, a 12px muted label, and a 24px bold number.

**Table** — header row `#FAFBFC` background with `#E4E7EC` bottom border, 12px/600-weight muted header labels; body rows separated by `#F1F2F4`, hover `#FAFBFF` when the row is clickable (drills into a detail view).

**Badge** — pill, 11px/600 weight, `padding: 3px 9px`, `border-radius: 6px`, colored text on a matching pale tint background per status (see palette table). Never a solid-fill badge.

**Buttons** — primary: `#2F6FED` fill, white text, radius 8px, weight 600, hover `#2A63D4`. Secondary/outline: white fill, `1px solid #D9DDE3` border, same radius/weight. Icon-only segmented control (e.g. sign-off method toggle): pill container `#EDEFF2`, active segment white with subtle shadow.

**Inputs** — `1px solid #D9DDE3`, radius 8px, `10px 12px` padding, 14px text. Read-only/auto-filled fields (e.g. BIN-found assembly details) get a flat `#F1F2F4` background with `#6B7280` text instead of a disabled look.

**Modal** — centered, white, radius 12px, `24px` padding, backdrop `rgba(16,24,40,0.45)`. Click-outside-to-close via a backdrop click handler that stops propagation from the modal body.

**Wizard progress** — a row of thin (5px) rounded segments, one per step, filled `#2F6FED` up to the current step, `0.5` opacity for the remainder. Step label underneath in 12px muted text ("Step 3 of 6 · Test readings").

**Icons** — [Lucide](https://lucide.dev)-style stroke icons only (no filled icons), stroke-width 1.6–2.2, sized 14–26px depending on context. Never mix in a different icon family.

## Applying this system in the real app

The shared UI primitives live in `packages/ui` (shadcn/ui). When implementing a screen from the [PRD](/docs/prd):

1. Map the token table above onto Tailwind theme values / CSS variables in `packages/ui/src/styles/globals.css` rather than hardcoding hex values in components.
2. Reuse the shadcn primitives (`Button`, `Badge`, `Card`, `Table`, `Dialog`) and restyle them to match these tokens once, instead of re-deriving the look per screen.
3. Where the prototype and a shadcn default disagree (e.g. badge padding, card radius), the prototype wins — it's what the client has already seen and approved.
